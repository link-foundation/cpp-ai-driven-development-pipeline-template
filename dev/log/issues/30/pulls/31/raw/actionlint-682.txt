**Workaround available today (verified end-to-end):** declare the labels through actionlint's own config, `.github/actionlint.yaml`:

```yaml
self-hosted-runner:
  labels:
    - ubuntu-26.04
    - ubuntu-26.04-arm
```

This is the documented config for labels the runner-label data doesn't know yet (docs/config.md); the rule keeps checking everything else.

Context: we run a project template whose full CI gate (its own chassis plus 7 generated projects, each linting its own workflows) moved to `ubuntu-26.04`/`-arm` ahead of the `ubuntu-latest` flip. On 1.7.12 (latest) every `runs-on: ubuntu-26.04` errors with "label ... is unknown"; with the config above the entire gate is green on both amd64 and arm64. Cross-referencing #761 (same error).

Revalidated against current actionlint 1.7.12 while updating https://github.com/link-foundation/meta-sovereign/pull/51 on 2026-10-28. `ubuntu-26.04` and `ubuntu-26.04-arm` still produce `label ... is unknown`. The same registry gap affects `windows-11-vs2026-arm`, now listed in https://github.com/actions/runner-images#available-images.

Minimal repro: a workflow with `on: push`, one job using `runs-on: ubuntu-26.04` (repeat for the other two labels), and `steps: [{run: echo ok}]`; run actionlint 1.7.12. Locally reproduced all three errors. Our consumer uses the documented narrow workaround:

```yaml
self-hosted-runner:
  labels:
    - ubuntu-26.04
    - ubuntu-26.04-arm
    - windows-11-vs2026-arm
```

This permits only the verified hosted labels and keeps other workflow validation enabled. Suggested upstream change: add these three labels to the built-in runner-label table and its tests, then release the validator. Linking here rather than opening another duplicate of #682.
