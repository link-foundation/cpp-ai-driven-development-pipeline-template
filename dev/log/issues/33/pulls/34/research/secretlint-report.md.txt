`@secretlint/config-loader@13.1.0` depends on `rc-config-loader:^4.1.4`. Current `rc-config-loader@5.0.0` adds native ESM and TypeScript configs, updates js-yaml, and removes its require-from-string loader. Please support v5 in a release with its Node >=22.18.0 floor and document the discovery migration.

Minimal reproduction of the current limitation:

```sh
npm view @secretlint/config-loader@13.1.0 dependencies.rc-config-loader
# ^4.1.4
# With secretlint 13.1.0 and recommended preset installed:
printf "export default { rules: [{ id: '@secretlint/secretlint-rule-preset-recommend' }] };\n" > config.mjs
printf 'No credentials here.\n' > clean.txt
npx secretlint clean.txt --secretlintrc config.mjs
# v4 loader cannot load the config; equivalent config.ts also fails
```

Our Node 26.13.1/npm 12.2.2 integration overrides rc-config-loader to 5.0.0. The existing JSON/YAML and malformed-YAML checks plus explicit `.cjs`, `.mjs`, and erasable `.ts` scanner cases all pass. Both `.mjs` and `.ts` cases fail without the override. Evidence and exact tests: https://github.com/link-foundation/cpp-ai-driven-development-pipeline-template/pull/34 (`scripts/test_secretlint.mjs`). No custom transpiler or namespace-unwrapping shim is needed.

Suggested dependency change: `"rc-config-loader": "^5.0.0"`, with engine `"node": ">=22.18.0"` (or a major Secretlint release if the current Node support contract requires it). `loadConfigDescriptor` already consumes `results.config`, which v5 unwraps itself.

Preserve existing discovery deliberately: v5 defaults to `.json`, `.yaml`, `.yml`, `.js`, `.ts`, then extensionless, whereas v4 also discovered `.cjs` automatically and preferred it/JS before JSON. An explicit `--secretlintrc config.cjs` still works. If automatic `.cjs` discovery should remain supported, pass the upstream `extensions` option with `.cjs`, retaining the intended priority and adding `.ts`/`.mjs` as appropriate; add CLI tests for automatic discovery and precedence. Do not pass the removed `defaultExtension` option.

Local workaround is a root dependency override with explicit config filenames where necessary. A supporting parent release will allow deleting that override. This report covers the parent integration/range and migration, rather than reopening the fixed js-yaml request in azu/rc-config-loader#30.
